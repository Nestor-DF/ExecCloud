JSON Config Format

Each service requires a .json config file that describes the service name, arguments, and execution options.

Required Fields

FieldTypeDescription
namestringUnique service identifier (must match binary filename)
descriptionstringHuman-readable description shown in the UI
argsarrayList of argument definitions (can be empty [])

Optional Fields

FieldTypeDescription
timeoutnumberExecution timeout in seconds (default: 30)
executionobjectWrapper command config (e.g. for mpirun)

Argument Types

Each object in args is passed to the binary as a CLI argument, in order.

typeUI InputPassed to Binary As
textText fieldString value
numberNumber fieldString value
fileFile uploadPath to uploaded file
output_fileAuto-generatedPath for binary to write output

Argument Object Fields

FieldRequiredDescription
idYesUnique identifier for the argument
labelYesDisplay label in the UI
typeYestext, number, file, or output_file
acceptNoMIME filter for file type (e.g. image/*)
extensionNoFile extension for output_file (e.g. .png)
arg_descriptionNoTooltip text shown next to the label

Execution Wrapper (optional)

Use the execution block to run the binary through a wrapper like mpirun:

"execution": {
  "wrapper": "mpirun",
  "wrapperArgs": ["-np", "4"]
}

This produces: mpirun -np 4 ./binary arg1 arg2 ...

Full Example

{
  "name": "filtro_cuda",
  "description": "Applies a filter using CUDA.",
  "timeout": 60,
  "args": [
    {
      "id": "input_image",
      "label": "Input Image",
      "type": "file",
      "accept": "image/*"
    },
    {
      "id": "output_image",
      "label": "Output Image",
      "type": "output_file",
      "extension": ".png"
    },
    {
      "id": "blockX",
      "label": "Block X",
      "type": "number",
      "arg_description": "Threads per block in X."
    }
  ]
}
